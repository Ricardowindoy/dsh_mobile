交互契约（都能在上面的面板里试）
按压反馈在 pointerdown

分段控件、端点卡、刷新按钮都在 pointerdown 立刻缩到 --set-press-scale（.97 / 120ms），不等抬起。apple-design 第一条就是杀延迟；:active 在 WebView 上首触可能不触发、滚动后可能钉住，所以另挂 .is-pressed 类做兜底 —— 只加类，不 preventDefault，不抢手势。

状态切换可打断、从当前值继续

切换数据态时新内容走共享层的 .stagger（enter-card，只碰 opacity + transform，400ms 弹簧近似）按 --set-stagger 50ms 逐条落位；动画期间不锁输入，连点会直接换目标，不等上一段放完。只碰 transform/opacity，不动画高度 —— 高度动画会让整页抖动，也违反白名单。

选中态用边框，不叠第二层阴影

端点卡的选中态是 inset 0 0 0 2px var(--set-ok)。Apple 的层级靠 fill 分层：分组表面已经有一层 --set-shadow，卡上再叠一层就是"两层浮起"。绿只上图形（4.14:1 满足非文本 ≥3:1），文字仍是 --set-text + 600 字重 —— 语义由词承载。

刷新保留上下文

点「刷新状态」：按钮进 busy（opacity .45 + 文案变「正在检查…」）但 label 不被替换成一个孤零零的「…」 —— 原代码 DockPanel 就这么丢上下文；该徽章本身已按用户决定整个移除（见上方记录），这条经验保留给设置页内的刷新按钮。

落地要点（对应真实代码的改造）

C1 · 内联样式 → 类 + 令牌

BTN / CARD 两个对象常量（写死 borderRadius:6/10、padding:'3px 12px'、lineHeight:1.7）整块删掉，换成 className + <style>：本页的 .act / .ep / .group / .row。React 里 style 对象每次 render 都新建，内联样式也无法响应主题切换（除令牌外没别的机制）。

C2 · 状态区改 inset-grouped + 同类项合并

Row 的 lineHeight:1.7 + justifyContent:space-between 换成 .group .row ： .row__label 左（ flex:1 1 auto; min-width:0 ）、 .row__value 右（ text-align:right; overflow-wrap:anywhere ），行缝由 .row + .row 的 inset 0 1px 0 承担。再加一层密度：三个 unit 合并成一行摘要（active · active · active），逐条明细进 <details>（默认收起）—— 状态区 6 行 → 3 行，手机一屏能多出一倍的行。合并不是隐藏：unit 名与状态都在展开层里，一字不改。

Row 的 lineHeight:1.7 + justifyContent:space-between 换成 .group > .row：.row__label 左（flex:1 1 auto; min-width:0）、.row__value 右（text-align:right; overflow-wrap:anywhere），行缝由 .row + .row 的 inset 0 1px 0 var(--set-line) 给出 —— 列对齐靠行缝，不靠 1.7 倍行距撑。

C3 · 长值不挤压相邻元素

probeUrl、unit 名、stateFile 必须 overflow-wrap:anywhere，且每一级 flex 子项 min-width:0。现状只在个别 span 上写了 overflowWrap，父 div 没写 min-width:0（flex item 默认 min-width:auto），窄面板仍会把「切换到此入口」按钮顶出去。

宿主主题令牌优先 —— 插件不自创色

这个分区跑在 DSH Web 里，颜色必须跟宿主主题走。稿子里的 --set-* 是「设计意图的表达」（apple / apple-night 的分层、语义色、灰阶），不是落地时插件要引用的令牌名：落地时每个颜色属性写成 var(--dsw-alias-…, var(--set-…)) —— 宿主有值就用宿主主题，脱离宿主单独预览时退回 apple 值，两条路都不出现裸色。材质（--set-material-*）与投影（--set-shadow）在宿主没有对应令牌：分区不画自己的材质与投影，层级只用宿主 fill 分层表达；侧栏那条材质是宿主的，别在插件里再画一层。

C4 · 一个实测结论：现状引用的 --dsw-* 大部分是幻影令牌

在 DSH checkout 的 packages/ 与 apps/ 里逐个 grep：--dsw-alias-text-primary / -text-secondary / -text-danger / -text-success / --dsw-alias-bg-subtle / --dsw-alias-border-subtle / --dsw-font-size-sm|xs|md 的声明数为 0（text-primary/-secondary 只出现在仓库笔记里，不在 CSS）。也就是说 BTN/CARD/Row 的 var(--dsw-…, #8884) 每次都在吃硬编码 fallback：边框恒 #8884、danger 恒 #e5484d、success 恒 #30a46c —— 插件切浅色/深色主题时这个分区不会跟。这是「宿主令牌优先」那条最重要的实装前提：先改成宿主真存在的令牌名（上表第四列），再谈分层。

C5 · 新增 warn 文案必须 zh / en 同补

F3 用了 warn 档，需要新键（现字典里只有 status.deviceOffline 一个词，没有「链路断」的成句说明）。建议：status.warn.linkDown、status.warn.whatToDo。原拟的 dock.warn.linkDown 作废 —— dock 徽章已整个移除（见上），不再需要为它配键。两栏一起提交，并跑一次键集合相等校验（zh 与 en 的 key diff 必须为空）。

C6 · 有意的语义改动（改动都要落到代码，不是只落在稿里）

① relay.reachable===true && deviceOnline===false：现状 tone='bad' → 改 warn（relayOk ? 'good' : reachable ? 'warn' : 'bad'）。② Windows 的 start_pending/stop_pending：现状 bad → 建议 warn。③ 空列表（config.empty / node.empty）：现状 danger → 建议中性 .empty + 点名 cordis.patch.yml，danger 只留给请求失败。④ dock 的 busy：现状整条换成 … → 建议保留 label + disabled。

C13 · 扫码配对分区（0.1.19 新增）

真实落点：client.js 的 pairBlock（在端点列表与数据面安装之间）+ host pairOp（mint/status/devices/revoke 四个 action 打 relay 管理路由）。稿内 P1–P4 四态：码活着（倒计时是事实，不是装饰）/ 未生成（中性引导，不是错误）/ 已过期（图变暗 + 文案换，不静默续期）/ relay 未启用（501 透传成 warn banner，点名 PhoneDevicesFile）。撤销是两步确认（× → ✓/×），防误触；QR 载荷只有 {v,relay,ca,code}，管理 token 不进 QR 不进 client 响应（插件测试有泄 token 变异检验钉住）。

C7 · 不动的部分（诚实性约束）

status===null 不兜底任何字段；online==='unknown' / state==='unknown' 不给 tone 也不给绿；verdict 与 body.error / HTTP xxx 一律原文；服务行显示 unit 名原文（svc.label || svc.name），不意译成「隧道/frpc/网关」这种丢掉 .service 后缀的说法。
