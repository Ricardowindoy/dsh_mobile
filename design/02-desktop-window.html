02 · 桌面 App 窗口

同一个连接页的宽屏形态。事实基线：src-tauri/tauri.conf.json 里窗口默认 420×760、resizable: true、没写 decorations（即 Tauri 默认 = 系统标题栏）。桌面不是"手机版放大"，它多出三件真实的事：窗口可被拉宽、鼠标有 hover、键盘 Enter 必须与按钮走同一条提交路径。0.1.19 起手机侧多了「扫码配对」主路径，但桌面看不到它：真实代码按 navigator.userAgent 非 Android 即隐藏整个扫码分组（桌面没有相机插件），所以本页各帧保持手动表单形态——这不是漏画，是真实行为。

01

宽了要收，不能拉满

900 宽时内容 max-width: 560px 居中、两侧各留白，表单不拉满。撑满会让两个字段的小工具窗读起来像后台管理系统，还把错误横幅推离它解释的那个按钮。

02

命中区是两档，不是一档

桌面档 .btn 下限 28px（本页故意不声明触屏目标，免得被 44px 规则误判）；触屏档要在同一个按钮上显式加 .btn--touch 抬到 44px。同一份组件，两档几何。

桌面形态要体现的真实差异

窗口顶栏 ≠ 原生标题栏

稿里用 .chrome 表达「窗口内沿的材质条」。

  • 配置没写 decorations → Tauri 默认 true，标题栏由系统画，Web 侧拿不到它。
  • 三个点只是示意，颜色只能用令牌灰；要真自绘顶栏得显式 decorations: false + 自定义拖拽区，属待决。
  • 窗口尺寸写在标题栏右侧（.win__geo），是为了让「420 还是 900」这件事在稿里可查。
鼠标 hover

只在 (hover: hover) and (pointer: fine) 里出现。

可点行 · 把鼠标放上来

base.css 已给 .btn:hover { opacity: .82 }；本页另给演示元素补了同档反馈。触屏不给 hover，否则样式被钉死在悬停态。

键盘 Enter 与按钮同路径

字段与主按钮在同一个 <form> 里，提交挂在 form 的 submit。

  • 真实代码已如此（connectForm.addEventListener("submit", …) → submitConnect()），所以不另加 keydown 处理器 —— 两处监听会双提交。
  • 桌面多出 Tab 顺序：地址 → token → 显隐 → 连接 → 自检 → 推送日志，与 DOM 顺序一致，稿子不重排。
  • 静态稿里表单是 onsubmit="return false"（稿子不导航）；落地时这条路径由真实 main.js 接管。
键盘焦点环

可聚焦控件在 :focus-visible 下有 2px brand 环 + 2px offset。

可聚焦行

静态稿没有键盘，所以用 .focus-demo 把环钉出来给人看；实现里它只在键盘路径出现，鼠标点击不打扰（base.css 已覆盖 .btn / .field__input（.row--tappable 曾列在其中，因没有任何页面使用它已被删除））。

命中区：桌面 28，触屏 44

同一组件两档几何，靠显式类名切换，不靠媒体查询猜。

.btn 桌面默认 .btn--touch 触屏

本页所有动作按钮用的是桌面档（base.css 的 .btn 下限 28px）。触屏档要显式加 .btn--touch（min-height: 44px），并在 html 或 .device 上把目标设备属性声明为触屏，闸门才会按 44px 那一档查。本页故意不声明：声明了整页的 28px 都会被误判成失败。（那条规则扫的是全文子串，所以这段说明里也没把那个字面量写全。）

宽屏断点的落法

真实代码 .screen-main 现在是 max-width: 460px，对所有视口生效。

  • 建议落法：@media (min-width: 700px) 把主区放到 560、卡片内距抬到 20px，chrome 保持整幅出血。
  • 判据是「无横向溢出 + 自检结果单行可读 + 更新卡不必滚动才够到按钮」，不是「看起来更大气」。
  • 420 档不跟着改：它就是手机排版，宽屏改动不该回头动窄屏。
