### B4 附注：为什么「桌面没有最大化按钮」不是一个排版问题

**现象**：桌面 App 装上后，系统标题栏里没有最大化按钮；窗口窄得像手机。

**根因（两层，均已实测到证据）**：

1. **按钮消失** —— 桌面安装包构建自 `github/windows` 分支，那份分支的
   `tauri.windows.conf.json` 写了 `maximizable: false`。tao 的 Windows 样式构造
   （`tao-0.37.2/src/platform_impl/windows/window_state.rs:247`）只在
   `WindowFlags::MAXIMIZABLE` 置位时才加 `WS_MAXIMIZEBOX` —— 不置位就没有那个按钮。
   这不是"按钮被藏了"，是**系统标题栏根本没有这一格**。
2. **看起来像手机** —— 同一份配置把窗口钉在 `width:420 height:760`。内嵌的 DSH GUI
   视口 = 420px < 宿主抽屉断点 768px → 宿主整体渲染成**手机抽屉档**，三栏布局
   根本不出现。relay 日志印证：Windows 设备 27 次 boot 全是 `vv=420x760 dpr=2`。

> ⚠️ 历史包袱：`github/windows` 那条 `maximizable:false` 当初是为了压掉一个
> "启动约 5s 后自动最大化"的症状（该症状本次未复现，relay 日志里窗口尺寸始终是
> 420×760）。**用"删掉最大化能力"去压症状，等于把用户的正常需求一起删了** ——
> 本轮改为直接给桌面一个正常尺寸的窗口，不再靠阉割窗口能力绕过。

**验证链（三层，每层都能红）**：

| 层 | 工具 | 判据 |
| --- | --- | --- |
| 配置契约 | `mobile/test/desktop-window.test.mjs` | G1 maximizable≠false；G2 width≥768；G3 不含 420/760 字面量；G4 设备名走 platformLabel；G5 桌面保留相册/粘贴；G6 不隐藏分组标题；G7 CSS 有 ≥700px 桌面档且主区 560；G8 窄屏主区仍 460 |
| 真实合并 | `scripts/verify/desktop-window-merge.mjs` | 用**真实 tauri-utils 2.10.2** 的 `read_from` 读四个平台：桌面三平台 `paths=2`（平台配置确实被合并）+ `maximizable=true` + `width=960`；Android `paths=1` + `420×760`（手机排版零影响） |
| 浏览器几何 | `scripts/verify/desktop-window-geometry.mjs` | 五档：**420 / 699 / 700 / 900 / 1280**。699 仍是手机档（主区 460、行 46），700 起进桌面档（主区 560 居中、行 34），全部零横向溢出。699/700 这一对是「断点被改」的探测器 —— 断点一旦挪动，这两档必有一档报红 |

**变异检验**（闸门必须能红，已逐个注入实测全红）：
`maximizable:false` → 红；`width:420` → 红；删平台配置 → 红；设备名写死 Android → 红；
桌面整区隐藏扫码 → 红；CSS 断点改 600 → 红；合并门禁的 `maximizable:false` → 红；
合并门禁删 linux 平台配置 → 红。

**本机跑不动的部分（如实登记，不许写"已验证"）**：
本机 `cargo check` 失败在**宿主依赖**（glib 2.66 < 2.70、缺 webkit2gtk-4.1），
与本次改动无关（本次未改任何 Rust）。因此"Windows 上真跑起来有最大化按钮"这一条
**仍属待验证** —— 需要在有桌面环境的机器上装新构建包确认。

**已知限制（如实记录，不写成已验证）**：
- Android 的站点清单是**清单探测**而非全量枚举（`CookieManager` 没有枚举 API）。清单
  取自 JetHub 里真实会打开的登录主机；用户若在别处登录了清单外的站点，那一站不会出现。
- 桌面端 cookie 删除按归一化 domain 精确匹配，不做后缀匹配 —— 清 `trae.net` 不会连带
  清 `api.trae.net`（各有独立行）。这是刻意的，避免误删其它站点。
- 1.0.24 的桌面端与 Android 端**编译**已由 GitHub CI 六平台构建校验通过；release、
  更新站、Gitee 发行版三处均已同步核验。

**真机修了三轮才通（每一轮的错误本地全都看不见）**：

| 轮次 | 真机报错 | 根因 | 闸门 |
| --- | --- | --- | --- |

| 1.0.25 | NoSuchMethodError: no static method listSites() | release 是 `isMinifyEnabled=true`，R8 把「只被 native 调用」的静态方法当无用代码删了，proguard 漏 keep | D8（find_class 的类 ↔ keep 列表对齐）+ `apk-jni-symbols.sh`（拆 dex 查符号） |

## G. 1.0.30 工作包：全部清除但保留配对（2026-11-18）

场景：用户原话——「不把配对信息去掉，但是清理掉所有 cookie 和本地存储，现在还是
