# dsh_mobile 设计集 · 设计规范（apple 风格）

这套稿子覆盖四个界面：**手机 App 连接页**、**桌面 App 窗口**、**DSH 设置页的「远程访问」分区**、**审批推送卡片**（0.1.19 新增：手机原生通知三态 + 桌面说明分区；通知由 Android 系统渲染，稿面用同一套令牌表达设计意图）。
三处共用同一份令牌与同一套组件层，落地时各自只改排版，不改数值。

## 一、风格与来源

| 层 | 来源 | 可否手改 |
| --- | --- | --- |
| 浅色令牌 | `dsh-ui-designer/styles/apple.css` | **不可**，逐字节原文 |
| 深色令牌 | `dsh-ui-designer/styles/palettes.json` 的 `apple-night` | **不可**，逐值原文 |
| 组件层 | 本设计集 `base.css` | 可改，但颜色只能引用 `--set-*` |
| 生成与验收 | `tools/gen-tokens.mjs` + `tools/check.mjs` | 可改，规则要能失败 |

上游署名：apple 风格移植自 [emilkowalski/skills](https://github.com/emilkowalski/skills)（Emil Kowalski，MIT），
快照 commit `f1090bec277140d02ed202440185ad9d02ac1490`。规则取自 WWDC《Designing Fluid Interfaces》
《Details of UI Typography》《Principles of Great Design》的整理版。

**深色为什么用 `apple-night` 而不是自己配**：本设计集第一版曾自创一套深色数值，与插件自带的
官方夜间档不一致（例如 brand 用 `#0a84ff`，官方是 `#3d9dff` + `brand-on:#041e33`）。规范上深色是
独立一层 palette，不是风格的自由发挥；现在由 `gen-tokens.mjs` 机械生成、`check.mjs` 逐值比对，
杜绝再次漂移。

## 二、硬规矩（上游主张，不是本仓建议）

1. **行为先于动画**：默认临界阻尼、response 0.4s；只有手势带惯性才允许回弹。
2. **响应杀延迟**：反馈在 pointerdown 出现，不是 click/抬起之后。
3. **可打断**：动画从当前屏幕上的值继续，不锁输入。
4. **空间一致**：从哪进就从哪出；popover 的 transform-origin 钉在触发点。
5. **材质表达层级**：chrome 用半透明 + `backdrop-filter`，内容从下面滚过去；**浅色半透明绝不叠在浅色半透明上**。
6. **文字压在材质上要加活力**：提高对比、略加重字重、加一点正字距。
7. **字距随字号变**：大标题负字距、正文近 0、小字略正；行高反向。
8. **动效只碰 transform / opacity**。
9. **减弱动态 ≠ 关掉反馈**：位移换成短淡入，缩放取消，颜色反馈保留。
10. **克制**：先删，再减，再修曲线。

## 三、令牌

浅色层与深色层由脚本生成，此处只列**语义与用法**（数值以 `tokens.css` 为准，别在这里抄一遍——抄了就会漂）。

### 画布与表面（三层，靠分层表达层级而非描边）

| 令牌 | 用途 |
| --- | --- |
| `--set-bg` | 画布：手机/桌面窗口底色，也是状态栏条带色 |
| `--set-surface` | 卡片 / 分组 / 弹层 |
| `--set-surface-2` | 控件底（输入框、次要按钮、chip） |
| `--set-line` | 分隔线（inset-grouped 的行缝） |

### 文字（三级灰阶）

| 令牌 | 用途 | 对比要求 |
| --- | --- | --- |
| `--set-text` | 正文、标题 | ≥4.5:1 |
| `--set-text-2` | 次要说明、行值、标签 | ≥4.5:1（11–13px 小字也要） |
| `--set-text-3` | **placeholder 与"确实没有"类弱提示** | ≥3:1，不可用于成句正文 |

> 第一版落地时曾把 `--set-text-3` 当"删掉的令牌"处理，理由是它压白卡只有 3.6:1。
> 现在按官方 palette 恢复它，但**限定用途**：只给 placeholder、图标性弱标注，
> 成句的说明文字一律 `--set-text-2`。这条限制由 `check.mjs` 之外的评审保证。

### 品牌与语义

| 令牌 | 用途 |
| --- | --- |
| `--set-brand` | 主按钮底、链接、焦点环 |
| `--set-brand-on` | 压在 brand 上的文字（深色档是 `#041e33` 而非白） |
| `--set-ok` / `--set-warn` / `--set-danger` | 自检通过 / 需注意 / 失败 |

**warn 有真实落点**：连接自检里"Relay 可达但设备离线"属于「网络通、链路断」，
既不是成功也不是失败，用 `--set-warn` + 文字共同表达（不只靠颜色）。

### 形状（8pt 基准）

控件 `--set-radius-sm` 8 / 卡片 `--set-radius` 12 / 面板 `--set-radius-panel` 18 / 胶囊 `--set-radius-pill`。

### 动效

`--set-spring-response` .4s、`--set-spring-response-sheet` .3s、`--set-ease-out`、`--set-ease-sheet`、
`--set-dur-press` 120ms、`--set-press-scale` .97、`--set-enter-scale` .96、`--set-stagger` 50ms。
`damping` 是上游原文但 CSS 无消费者，只作为注释保留，不写成令牌（写了就是撒谎）。

### 材质

`--set-material-bar` / `--set-material-blur` 20px / `--set-material-saturate` 180% / `--set-material-edge`。
深色档官方未提供材质键，由 `--set-surface` 同 RGB + `.72` alpha **派生**，派生式写在
`gen-tokens.mjs` 注释里并由 `check.mjs` 断言。

| 类 | 字号 | 字距 | 行高 | 用在哪 |
| --- | --- | --- | --- | --- |
| `.t-large-title` | clamp(26px, 7.6vw, 34px) | −0.022em | 1.05 | 手机页主标题 |
| `.t-title` | 17px | −0.016em | 1.2 | 卡片标题、桌面窗口标题 |
| `.t-body` | 15px | −0.003em | 1.47 | 正文基线 |
| `.t-footnote` | 12px | +0.01em | 1.45 | 次要说明、字段说明、时间戳（合并了原先 13px 的 callout 档：本设计集没有页面用到它，留着等于撒谎） |

## 五、组件层（`base.css`）

页面**只允许**引用这些类与 `--set-*` 令牌；出现裸色值、动尺寸属性、触屏命中区 <44px 都会被闸门拦下。

| 类 | 说明 |
| --- | --- |
| `.chrome` + `--top/--bottom/--side` | 半透明材质条（顶栏、底部栏、设置页侧栏） |
| `.card` / `.card--panel` | 分组表面 / 面板级（18px） |
| `.group` + `.row` | inset-grouped 列表：设置页主骨架，行缝用 `--set-line` |
| `.btn--primary/secondary` | 两档动作；文字动作已按用户要求全部改为图标按钮 |
| `.btn--touch` | 触屏档命中区 44px（桌面默认 28px） |
| `.field` + `__label/__input/__help` | 竖排字段（标签在上、输入在下）—— 只在"输入本身就是主角"时用 |
| **`.field-row`** + `__label/__control` | **同行字段**（标签左、控件右）：设置页与连接页的默认形态，每字段一行（44px 触屏 / 34px 桌面） |
| `.group--fill` / `.group--inset` | 分组容器：填充白卡 / 只有描边（inset） |
| `.group-h` / `.group-foot` | 组上方的分组名（12px）/ 组下方的脚注（12px 一行）—— 说明挂组下，不挂每个字段下 |
| `.pill` + `.dot--ok/warn/bad` | 状态：颜色 + 文字一起表达 |
| **`.st__pill`** | **状态胶囊**（2026-11-08 控件规范 `.wb-badge`）：12px/500、`--set-radius-sm` 圆角、色点 `currentColor`、surface-2 底 + 派生染底/30% 描边 + ink 文字；状态值不再裸文字 |
| `.banner--bad/--warn` | 错误与需注意，由 danger/warn 与 surface 混色派生 |
| `.empty` | 空状态，必须区分「从未产生」与「确实没有」 |
| `.sheet` | 底部弹层，圆角只在上沿 |
| `.enter` / `.enter--2` | 成组入场，stagger 50ms |

### 动作按钮规则（用户 2026-11-07 定：动作一律图形，不用文字按钮）

1. **所有动作按钮用图标，不用文字**：刷新（圆形箭头）、复制（重叠方框）、切换（双向箭头）一律
   图标 + `aria-label`/`title` 承载语义。图标本身 `aria-hidden`，读屏读按钮名。
2. 视觉 32×32、图标 16px，命中区用 `::before` 扩到 **44×44**（触屏档按钮本体 44）。
3. busy 态：图标旋转（只碰 transform）+ `disabled` + `aria-label` 切到「正在检查…/切换中…」——
   状态既可见又可读，不把文案换成一个「…」。
4. 状态徽章（「使用中」）不是按钮：保留文字并配 ✓ 图标 —— 图标是冗余编码，词才是语义。
5. **刷新按钮挂在「状态」分区标题行右侧**（2026-11-08 用户定）：与标题同一条基线，图标视觉右缘
   与下方卡片右缘对齐（32px 按钮里 16px 图标两侧各空 8px，用负 margin 吃掉留白；触屏档同理）。
   不放在状态卡底部。
### 密度规则（本轮新增，由"UI 太丑 + 移动端信息密度太低"逼出来）

这是本设计集最容易做错的一档，单独列成硬规矩：

1. **字段默认同行，不竖排**。竖排（label 上 / input 下）每个字段吃掉标签行 + 输入行 + 间距 ≈76px，
   两个字段就占掉 390×844 屏的近三分之一。同行后每个字段一行。
2. **标题不堆叠**。一页里最多两级标题文字（大标题 + 正文）。曾经"29px 大标题 + 副标题 +
   17px 卡标题 + 13px 卡说明"四级堆叠，标题区就吃掉 40% 屏。大标题上限 **24px**
   （iOS 导航标题 17px；34px 的大标题只用于"个人中心"级首屏）。
3. **同类项合并成一行**。三个 systemd unit 合并成一行摘要（`active · active · active`），
   逐条明细收进 `<details>`（原生、键盘可达、默认收起）。原文一字不改，只是不默认展开。
   状态区从 6 行降到 3 行。
4. **说明合并到组下**。每个字段下面挂一句说明 → 合并成一条 `.group-foot`。
5. **不包"浮起的卡片"装两个输入框**。表单用 inset-grouped 分组，不用一块砖。
6. **桌面档同样要密度**：桌面窗口只有 420–560 宽，竖排字段让"两个字段"占掉 1/3 窗高。

## 六、三端各自的约束

### 手机 App 连接页（390×844 / 320×568 / 390×400 键盘弹起）

- 三段式骨架：顶栏材质条 / 主区（`margin:auto 0` 在剩余高度居中）/ 贴底材质栏。
  **不要用 `justify-content:center`**：键盘压矮视口时它会把顶部内容推出可滚动区。
- 状态栏条带色 = 页面 `--set-bg`，由 `main.js` 推给原生 decorView（不让两端各判一次明暗）。
- 安全区交给原生 insets，CSS 的 `env(safe-area-inset-*)` 在这个 WebView 里恒为 0。
- **动作一律图形按钮**（`.icon-btn`，44×44、图标 18、`aria-label` 承载语义）：
  「连接自检」（放大镜）、「推送日志」（文档）—— 旧 `.btn-ghost` 文字动作已删除。
  主 CTA「连接 dsh」保留文字：动作主体用文字比图标直接；更新卡两个按钮因状态语义
  （下载中/立即安装/重试下载）保留文字。
- **字段同行**（`.field-row`）：标签左、输入右。输入框去掉自身底色与描边（分组已是容器），
  只留右对齐的文字；token 的显示/隐藏按钮仍在行内占位（44px 命中区）。
- 大标题 24px，副标题 13px 一行，说明合并进 `.group-foot`。

### 桌面 App 窗口（1280×800 内切 420×760 与 900×700）

- 同一个连接页的桌面形态：`tauri.conf.json` 里窗口 420×760 且 `resizable: true`。
- 宽起来后主区 `max-width` 收到 460–560px，两侧留白，**不拉满**（表单拉满会读起来像后台管理系统）。
- 键盘 Enter 与按钮提交同路径（挂在 `<form>` submit）。
- 字段同行（`.frow`，桌面档行高 34px）；标题同样 24px —— 桌面窗口窄，别用大标题撑场面。

### 设置页「远程访问」分区（桌面 1280×800 / 手机 390×844）

- 宿主是 DSH Web 的设置面板，插件通过 `settings.section` 注入；稿子画的是**分区内容**，
  外壳（导航、标题栏）按宿主现状示意，不擅自重设计宿主。
- 现状是内联样式（`BTN`/`CARD` 写死尺寸与色），落地要改成令牌引用。
- 信息结构保持既有事实：状态区（端点 / Relay / 服务单元 / 结论）+ 端点列表（可切换）+ 配置事实。
  **不新增功能，只重排层级**。
- **状态值用胶囊展示**（2026-11-08 控件规范 `.wb-badge`）：节点在线状态、Relay 可达/设备在线、服务单元状态、
  端点「使用中」一律用 `.st__pill`（实装 `.wb-badge` 同骨架），不再用裸文字 + 颜色。
  骨架 = 色点 currentColor + 12px/500 + `--set-radius-sm` + 3px 10px + flex wrap 8px；
  染底走 gen-tokens 预派生档（0.04/0.05，12% 会被 4.5 对比断言拦）、描边统一 30%
  （`--set-ok-line/-warn-line/-danger-line`），不用 color-mix（chrome100 静默失效）。
- **刷新按钮在「状态」标题行右侧**：与标题同一行、右对齐，图标视觉右缘与下方状态卡右缘齐平。
- **状态区按"同类一行"折叠**：三个 systemd unit 合并成一行摘要（`active · active · active`），
  逐条明细进 `<details>`（默认收起）。**原文一字不改** —— unit 名与状态都还在展开层里，
  只是不默认展开。状态区从 6 行降到 3 行，手机一屏能多出一倍的行。
- 端点卡同理：三个 unit 名合并成一行可点开的摘要行（`.ep__disclose`），不默认展开。
- 诚实性约束（本仓规范）：`missing/null/空串`不得兜底渲染成正常值；"未检查"要看得见是未检查 ——
  且两种"未检查"要说清差别（配置已回 vs 两个请求都没回）。
- **移动档（≤767px，同宿主 SettingsRoot 断点）**：390px 实测桌面档是坏的（208px 侧栏把正文
  压到 132px、分段钮竖摞 96px、文档高 12639px）。移动档跟宿主做法：导航变横向滚动条
  （横滚写在滚动元素自己身上、父级 flex 子项 `min-width: 0`，漏一条整页溢出 345px）、
  行回归触屏 44px/15px 字号、长评审材料默认折叠、面板底部留 `env(safe-area-inset-bottom)`。
  命中区走闸门规则 8（`<html data-target="touch">` 声明触屏目标）。

## 七、验收

```bash
node design/tools/gen-tokens.mjs   # 令牌由上游重新生成
node design/tools/check.mjs        # 闸门，会失败（规则条数以它自己打印的为准）
```

规则清单只有一个真值来源：check.mjs 里的 RULES 数组，汇总行由它生成，加规则忘了登记会自己报错。
**文档里不写条数** —— 写了就会漂（本轮已经漂过三次：六条→九条→十三条）。
每条都做过变异检验 —— 没被咬过的规则只是装饰。注入并复活的违规：

| 注入 | 期望 | 结果 |
| --- | --- | --- |
| 裸 hex / 裸 rgb() / 颜色关键字 | 令牌优先 | 报红 |
| 内联 `style="color:#fff"` | 令牌优先 | 报红（曾漏：只扫 `<style>`） |
| 拼错令牌 `--set-warnn` | 令牌存在性 | 报红 |
| `transition: width` / `transition: all` | 动效白名单 | 报红 |
| `@keyframes` 动 height | 动效白名单 | 报红（曾漏：正则要求换行） |
| `color-mix()` 混色 | 兼容底线 | 报红（**新规则**：WebView chrome100 上整条静默失效） |
| 删掉 base.css 的 `[hidden]` 规则 | 共享层硬规矩 | 报红（**新规则**，见下） |
| `<script>` 里 `el.style.color = '#…'` | 令牌优先 | 报红（曾漏：只扫 `<style>`；且 `style.x =` 赋值形态一度漏检） |
| 页内 `<style>` 定义一个没人用的类 | 死类 | 报红（曾漏：只查 base.css；第一版因正则转义多一层而**全量误报**，改用切词集合后正确） |
| 把 `--set-text-3` / `--set-ok` 当文字色 | 文字色白名单 | 报红（**新规则**：浏览器探针实测 3.36/4.14 不达 AA，前十条文本规则全绿） |
| 触屏 `min-height:32px` | 命中区 | 报红 |
| `box-shadow: var(--x));` 多一个括号 | 畸形声明 | 报红（**新规则，见下**） |
| 手改派生 tint 值 / 官方深色值 / 浅色层一个字节 | 派生复算 / 令牌同源 | 报红 |
| 删掉浅色的 `--set-ring`（深色块仍留着） | 主题完整性 | 报红（曾假通过） |

反向也要成立（不误报）：`base.css` 里写 `url("data:…;…")` 不报畸形声明；
正文用 `<code>` 描述那个括号 bug 不报命中区也不报畸形声明；
桌面稿正文提到 `data-target="touch"` 字面量时按 28px 档判、不报红。

下列规则都是被真实缺陷逼出来的，不是预先设计的（括号里写的是它当时漏掉了什么）：
1. **畸形声明**：`base.css` 里 `box-shadow: var(--set-shadow-lift));` 多一个右括号，
   浏览器静默丢掉整条声明，面板级抬起阴影从未生效 —— 原六条全部放行。
2. **主题完整性**：浅色块删掉某令牌、深色块还留着时，"令牌存在性"只看名字在不在，
   于是浅色模式静默解析为空却绿灯。
3. **派生复算**：注释写着"check.mjs 复算"却没实现，那是空头承诺；实现后立刻
   抓到 placeholder 算式两套不对称（浅色用官方原值、深色取中点）被误判成一致。
4. **兼容底线**：`color-mix()` 要 Chrome 111+，而 vite `build.target=chrome100` ——
   在 Android WebView 上是整条声明静默失效。文档里写了"不用它"，却没有任何规则
   拦得住，所以补成闸门。
5. **共享层硬规矩**：`base.css` 缺 `[hidden]{display:none!important}` 时，稿子首屏
   画出一个空的错误条（DOM `hidden=true`、计算样式 `display:flex`）。组件层漏一条，
   所有引用的页面一起静默出错；前七条文本规则全部放行。

反向也要成立（不误报）：`base.css` 注释里解释"不用 color-mix()"不报兼容底线；
正文用 `<code>` 描述括号 bug 不报畸形声明；桌面稿正文出现 `data-target="touch"`
字面量时按 28px 档判、不报命中区。
