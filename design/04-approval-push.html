审批推送到手机

agent 请求审批时，已配对的手机会收到通知卡片，可直接允许一次或拒绝；点击卡片打开 App。

  • 只有手机在线订阅时才接管审批；手机不在，审批照常留在桌面。
  • 接管后无人应答＝拒绝（超时自动拒绝，沉默不是同意）。
  • 提问通知不含问题文本，只提示去 dsh 查看。

与真实代码的差异 / 待验证

项真实代码现状这张稿子的做法为什么 / 怎么落地
通知渲染者 Android 系统（NotificationCompat，渠道 dsh-approvals IMPORTANCE_HIGH）；圆角/阴影/字体由系统决定 用 apple 令牌画"设计意图"：实色 surface 卡 + 面板级圆角 + 抬起阴影 稿面不是像素级复刻系统通知；落地以系统渲染为准，令牌只约束 App 内回执与桌面分区。
action 语义 addAction(0,"允许一次"/"拒绝", PendingIntent) → AnswerReceiver → Rust nativeAnswer（设备 token header POST）；decision 闭集两侧各验一次 两个 44px 按钮；允许=brand 实心，拒绝=中性面 + 描边 「允许一次」是唯一授权档（没有"始终允许"）；重放同一 id 被 relay 410 拒绝，卡片更新为已处理。
超时提示 插件 askTimeoutMs=110000 后 resolve undefined → unavailable；通知由 retract 撤回 卡片脚注写明「110 秒内无人应答将自动拒绝」 稿面新增的脚注：真实 Kotlin 卡暂未画这行（系统通知空间有限）；落地可作为 BigText 末行，需真机看折行。
提问卡正文 恒「点击查看并处理」；问题文本不进推送载荷（插件变异检验钉住） 与真实一致 隐私规则来自 approval-popup-bridge 先例：通知栏可能被旁人看到。
进程被杀 v1 无常驻服务：进程死则 SSE 断、无通知（README 已知限制） 未画"离线错过"态 待验证：真机杀进程后是否确实无通知、重开 App 后 pending 表是否补发（插件重连重放语义）。
POST_NOTIFICATIONS 被拒 Kotlin 捕获 SecurityException 降级为 App 内可见（cards 表仍在） ③ 的回执态即该降级的可见形态 权限拒绝不崩、不静默丢卡。

闸门：node design/tools/check.mjs。本页颜色全部来自 var(--set-*)， 动效只碰 transform / opacity，action 命中区 44px。语义规则（claim / fail-closed / retract / 隐私） 的权威在插件与 relay 测试，不在稿子。
